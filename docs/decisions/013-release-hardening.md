# ADR-013 — Release hardening and operational boundaries

Status: accepted for the owner-authorized Phase 7 engineering milestone. Hosted activation remains separately gated.

The MVP stays online-first. The production service worker caches only the public offline notice and two fixed app icons. Navigations use the network and show the notice on network failure; private HTML, REST, auth, RSC, recovery buffers and shared content never enter Cache Storage. Registration failure does not block the app. The worker has a narrow same-origin CSP permission and its script cannot be persistently HTTP-cached. Chrome installability is checked with a normal temporary profile; incognito correctly prohibits installation. Keyboard, browser accessibility-tree, axe, mobile-width and enlarged-text checks supplement semantic review; they do not claim manual certification on every browser or assistive technology.

Errors produce closed operational events containing only event name, UTC time, generated request ID, status and validated error code. Never pass request URLs, identifiers, cookies, query/body data, exceptions or stacks. Per-replica minute bounds are 60 server errors, 12 other client errors and six rate-limit errors; sampling can omit individual events. Responses still receive unique request IDs. Log sink failure cannot break error handling. Database-coordinated request limits are tested with independent clients and concurrent consumers. Proxy trust remains off until the owner verifies header sanitization.

The inherited minimatch advisory requires a major transitive update. Rather than ignore it, the lock explicitly overrides affected minimatch 7–10 consumers to stable 11.0.2 (published 2026-10-28). Its public matching interface remains compatible with the pinned lint consumers in the verified install/lint/type/build checks. The override and additional glob matcher are reviewed dependency changes; the 24-hour supply-chain policy stays enabled. No paid or AI dependency is added.

Backups use a consistent PostgreSQL 17 exported snapshot for both pg_dump and READY object identities. Every referenced immutable object is read privately and checked against SQL size/SHA-256. The versioned backup envelope streams AES-256-GCM with random salt/IV, HKDF-SHA256 and an independently protected 32-byte key file. The manifest and complete payload are authenticated before parsing or restoring; per-file hashes are checked. Atomic publication cannot replace an existing backup. Limits are 2 GiB total and 10,000 frozen objects; exceedance fails without truncation. Plaintext preparation/extraction uses private temporary directories and is removed on normal completion/failure; approved hosted operations must use protected tmpfs/encrypted temporary storage and handle interrupted-job remnants.

The local rehearsal deliberately restores into a new UUID-named database and an empty dedicated bucket. It does not overwrite sources or an existing target. Old sessions, one-time auth tokens and share links are invalidated before a restored target may be exposed, and interrupted PENDING snapshots become FAILED. The source retains later edits. These are trusted operator backups, not public project imports: possession of the protected backup key grants access to private SQL and object content.

The approved policy retains the latest backup on each of 30 successful UTC backup dates, preserving older successful dates when jobs are missed. The retention command emits a plan only; it never deletes files, provisions storage or activates a schedule. Unknown filenames stay protected. The backup key must be separately recoverable from the destination, and hosted access/retention/restore must be verified before release.

Coolify remains the owner-selected deployment target. The release Compose template proposes separate environment namespaces, dedicated SQL owner/runtime identities, private storage volumes, whitelisted app variables and digest-pinned images. The Garage API shares the app network namespace on loopback, with no published S3/admin/RPC ports. This is a one-replica MVP profile; recreating the app must recreate its storage network attachment. Separate runtime/backup grant profiles are tested locally. A database schema owner is never an app credential.

No hosted resource, DNS, production migration, deployment, off-host job or retention deletion is activated. The owner's answer “Coolify” selects the deployment/control plane; existing underlying SMTP and protected off-host S3 configuration still require read-only discovery and verification. The authorized Mac became unavailable during Phase 7; no unverified hosted integration is claimed.
