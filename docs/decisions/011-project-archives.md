# ADR-011 — Versioned transactional project portability

Status: accepted within approved Phase 5 (#29–#30).

Use a strict JSON envelope `format: inkwell.project`, `version: 1`, UTC export time and validated domain collections. Technical bounds: 8 MiB input/output, 10,000 archive rows, depth ≤64 before recursive validation, existing rich-text schema 1 and its text/node/URL limits. Reject unsupported versions, unknown fields, assets and malformed graphs before writing. No asset model has shipped yet; `assets: []` is explicit rather than implying binary portability.

Export runs in one repeatable-read transaction and reads explicit field allowlists in bounded pages. Include project and all stories, shared/local canon, overrides with base snapshots and field presence, typed relationships, root/child groups, scenes/order/status/duplication ancestry, scene canon references, and relevant Idea Vault sources/classification/links/conversion snapshots, including archived rows. A source Idea linked into other projects is included once, but unrelated destinations/relationships/IDs are excluded. Account data, workspace IDs, auth/session information, protocol request keys/hashes, derived vectors and save receipts are never exported. The archive is private data; downloads are authenticated and no-store.

Import preview validates the exact archive without writes, lists counts and explains semantics. Explicit import always creates a separate project and fresh IDs for domain records, including relevant Ideas. It never replaces an existing project or merges creative content. Matching normalized category/tag names reuse workspace classifications without rewriting their display names. Source versions/timestamps, canon override bases/conflict state and conversion snapshots are preserved; operational request keys/hashes are generated anew.

Graph validation covers per-collection unique IDs, all typed references, same-story canon applicability, canonical position uniqueness, root/child nesting/archive constraints, acyclic scene duplication, override shared bases/presence and compatible relationship/conversion targets. Table-specific remap keys allow independent source tables to use the same UUID. Source-first bounded scene inserts preserve immutable ancestry. Classification/roots/children/links/provenance commit in one 30-second database transaction; any failure rolls everything back, including new taxonomy. No assets are staged, remote URLs fetched, permanent deletes performed or production migration run.

Limit heavy import/export endpoints independently. A lost import response can leave a successfully imported separate project; check Projects before retrying to avoid a duplicate. Future archive versions need explicit migrations and round-trip compatibility tests. Large-archive runtime limits, VPS throughput and binary assets remain release/future-version concerns, not silent partial imports.
