## Behavior and integrity evidence

Rich documents and derived search text persist with a format version. Safe grammar/URL/size validation rejects unsupported structures; HTML-like text remains literal, not executable. SQL tests prove scoped categories/tags and FK rejection, filtered generated-vector search, stable cursors, stale-write rejection, multiple qualified references, archive/restore retention, all three independent target copies, immutable snapshots, rollback, exact-one conversion target checks and canonical scene appends.

Repeated conversion requests use workspace-bound idempotency keys and canonical hashes. Parallel identical retries create one target; conflicting key reuse fails. Replays return the original post-conversion version, so an intervening edit cannot be silently overwritten by a stale editor. Read responses explicitly allowlist fields, including replay responses; hashes/keys/snapshot internals are not serialized. Unsupported future document formats fail safely.

Browser journeys use real registration/verification/sign-in and loopback SMTP, not an auth bypass. They cover capture, formatting, classification, all conversions, multiple links, search facets, archive/restore, read-only source navigation, cross-account denial, escaped HTML text, replay responses and axe checks on desktop/mobile. Delayed tag-response checks prevent a content save racing an unfinished classification mutation. A slow-script regression verifies controls wait for attached client handlers before accepting a draft; this also fixes a real first-field input loss observed in the full suite. Existing account/project/session tests still pass.

## Operating and scope limits

The two migrations create workspace-scoped vault tables, guarded typed relationship/provenance FKs, shared Character and ordered Scene foundations, generated weighted tsvector/GIN, content-format versions and backlink indexes. They were applied only to local/disposable databases. Production still requires an approved migration, backup/recovery and deployment plan with least-privilege roles.

Characters are minimal shared project records and scenes are appended in one canonical sequence. Full Story Bible/local canon/override management and Plot Board/grouping/reorder tools remain Phases 3/4. Story conversion copies complete plain text to the existing synopsis; original formatting stays in the source/snapshot and structured Character/Scene targets. Category/tag creation, assignment/removal and paged selection are included; global taxonomy rename/delete management is not added. No permanent creative deletion API exists.

Search uses PostgreSQL's simple dictionary and websearch syntax, stable time/ID paging and AND tag filters. No stemming/fuzzy or corpus-scale latency claim is made. Readonly target source previews are bounded; Story/Scene links navigate to paginated vault filters for further retrieval. Explicit saves remain; autosave/recovery/offline buffers are Phase 5. No service worker caches private content. AI is disabled; no provider or paid infrastructure dependency is introduced.

Hosted SMTP/HTTPS/proxy/role verification, real-device Safari/PWA installation, manual screen-reader/zoom audits, hosted backup restore, retention policy and release-scale performance/security review remain staging/release gates. Automated axe is not a full accessibility certification. The existing Mac preview remains the earlier static Phase 0 shell; no new live application URL is claimed.
